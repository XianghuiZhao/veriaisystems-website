Frequently Asked Questions

Do I need to write DSL manually?

No. VeriAI is designed to transform natural language requirements into executable DSL automatically. Engineers can describe expected system behavior in plain language, and the system generates deterministic validation rules.

How is this different from traditional testing frameworks?

Traditional testing validates implementations — unit tests, integration tests, and simulation-based checks. VeriAI focuses on validating system behavior directly from requirements. Instead of asking “does the code work?”, we ask “does the system behave as specified in real-world conditions?”.

How does the DSL integrate with existing toolchains?

The DSL is designed as an abstraction layer. It can be mapped to existing test environments, simulation frameworks, or real hardware interfaces. The goal is not to replace your stack, but to provide a deterministic validation layer on top of it.

What types of signals and interfaces are supported?

The platform is designed for multi-signal environments, including CAN, Ethernet, and analog signals. It focuses on validating cross-signal dependencies and temporal behavior across heterogeneous systems.

Is this intended for simulation or real hardware validation?

Both. VeriAI is designed to operate across simulation environments and real-world signal inputs. The core principle is consistent validation logic regardless of the execution environment.

Does VeriAI control the system under test?

No. VeriAI is strictly a validation system. It observes and evaluates signals but does not control or interfere with the system or environment. This ensures clear system boundaries and avoids unintended side effects.

What stage is the platform currently in?

VeriAI is currently in early-stage development. The core concepts, DSL, and validation engine are being actively designed and prototyped.

How does the system interpret natural language requirements?

The system maps structured natural language patterns into deterministic DSL rules. The focus is not on general AI interpretation, but on precise, unambiguous transformation into executable validation logic.

Does this rely on cloud-based AI models?

No. The system is designed to operate locally with controlled transformation logic. This ensures deterministic behavior, reproducibility, and suitability for safety-critical environments.
